# Tasty Travels Origin 插件

模板 ID `tasty-travels-origin`。原版是投放饮品与碰撞合成试玩；支持片头、GO、两行标题、CTA 节奏。默认纯试玩，第 20 次有效操作首跳，之后间隔 10/8/6/4，末间隔循环。

工作台「启用剧情开场（火焰里的怪物）」对应 `story.enabled`，默认及旧任务关闭。当前固定复现用户截图中的章节和英文对白：点击逐条推进，打字时点击立即显示全文，支持跳过，最后 Continue 进入游戏。场景与头像使用用户截图原图的 CSS 区域显示，标题、对白、滚动和按钮使用 DOM；仅开启时内嵌图片，无外链资源。内容编辑留待后续。

同时开启视频时按视频 → 剧情 → playable 衔接，剧情的 Continue 替代视频 GO；关闭剧情恢复原 GO 配置。剧情期间继续预加载游戏，保持静音和暂停，不上报 playable 操作或触发 CTA；结束剧情后才开始 playable 阶段。已就绪直接进入，未就绪显示原 Loading；重玩不重复剧情。开关修改仅需重新打包。

剧情已验证手机完整对白、Continue 后真实投放、视频后跳过、原 GO 配置替换、横屏和 30 秒资源延迟下的 Loading 兜底；自动化覆盖打字暂停、提前显示全文、滚动与点击区分、结束去重、游戏输入门控及配置保存/预览/导出。

工作台「游戏设置 → 投放等级加成」对应 `gameplay.spawnTierOffset`，接受 0–8 的整数，默认及旧任务均为 0。原版固定投放序列 `spToolAll` 的每项统一加上该值，并封顶内部等级 8；等级 9 仍由碰撞合成触发通关。保留投放顺序和循环长度，NEXT 同步显示加成后的下一件，包含序列末尾回到首项的预告。每次重玩从原序列重新应用一次加成，不累计；合成进度仍只统计实际合成等级。保存后预览生效，导出只需重新打包。

一次被引擎接受并消耗待投放物的操作记一步；空抬手、点击下载、单次投放产生的多次连锁合成不重复记步。进度为事件发生时已合成最高等级 / 9，属于等级进度，不是剩余操作数估算。最高级触发原版 EndStep 为 win，原生越界 EndStep 为 fail；不从 CHALLENGE_SOLVED 等误标的原生触摸统计推断结果。

工作台「游戏设置 → 允许重玩」对应 `gameplay.allowReplay`，默认关闭，旧任务也默认关闭。开启后，成功或越界失败显示英文重玩按钮，结果使用 `continue_playing: true`。点击先通过 `novvy:replay-cta` 触发统一 CTA-card 跳转，再从缓存重建原版 GameScene；新场景绘制后上报同段 `onReplay`。恢复初始食物、金币、订单和引导，投放计数、等级进度与 CTA 阈值归零，片头与阶段不重复。清理旧场景计时回调、补间动画和订单订阅，复用原版两条不同的背景音轨。设置修改只需重新打包。

原生下载触摸停止传播，抬手不会误投放；CTA 不结束段。结果后的触压由共享 CTA bridge 处理，不调用原版跳转。片头期间预加载引擎与场景，首帧绘制后暂停玩法并保持静音，等待片头退出（含 GO 点击）才恢复；已就绪时直接进入游戏，未就绪时显示原版 Logo 与进度条兜底。纯试玩正常显示 Loading，后台暂停物理与声音。

浏览器实测有效投放、碰撞合成、11.11%/22.22% 进度、原生 CTA 与后续继续操作；通过本地测试入口触发最高级和越界结算，验证连续重玩、片头只播一次、投放进度重置、两条不同背景音轨 ID 保持不变，重玩后仍能真实投放并碰撞合成。自动化验证结果分流、去重、视频门控、重玩加载失败重试与设置保存/打包。生产 SDK、真机 WebView、完整最高级手动通关未实测；测试入口和 QA SDK 不进入导出物。

三套共同验收与限制见 `docs/three-origin-templates-verification.md`；已测试 390×844 手机视口内真实操作、横屏和视频 GO 链路。

转化统一复用 core CTA bridge：步数循环已触发后，通关不重复自动跳转；关闭重玩时最终通关后普通触压可再次转化，开启时不武装逐次触压跳转，重玩按钮每次只触发一次 CTA。Canvas 下载按钮保留 `cta_click` 且不重复。无 SDK 的编辑器预览只记录触发，不调用原版跳转兜底。

合成完成时立即补报当前投放步的最高等级进度，最终 100% 先于 win。Grill Sort 与本模板的异步补报沿用当前 `step`，不增加 CTA 的有效操作计数；SDK 的 `interaction_count` 仍遵循 SDK 自身计数规则，不能视作严格去重的手势数。
