# Colorever New 图案制作

## 从这里开始

以下命令从仓库根目录运行。根据本文件位置向上三级定位根目录，不依赖绝对机器路径。

1. 读取 [设计规范](../../../docs/colorever-pattern-design.md) 和 [数据契约](references/pattern-contract.md)。它们是日常制作所需的固定上下文。
2. 查看 Git 状态，确认本次图案 ID 和用户要求。修改已有图案只读它的 JSON、装饰模块及对应注册片段；新增图案按契约创建，不遍历现有图案寻找写法。
3. 先设计并审视完成图的美感，再验证开局。优化已有图案时与修改前的实际渲染比较，不能把有层次的图案降成粗糙图标。默认只修改 `colorever-new` 的目标图案和必要配套，不同步其他模板，不顺带改材质、渲染或玩法。

日常不需要重读根 README、模板完整 README、历史对话、其他图案测试或整个引擎。需要编辑共享注册文件时只取相关片段，保留其他条目。用户明确要求分析源码时，按该任务读取。

## 美感与辨识度优先

- 图案首先要作为一幅完成图好看：比例、构图、配色、材质和细节层次成立，同时能辨认主体。不要求完全像参考图，也不能以“看得懂、步数少”替代美感验收。
- 允许改姿态、放大局部或重画同题材主体，但保留建立美感的结构。戒指应有合理的戒圈比例、内外壁明暗、金托或镶爪、宝石切面；不要把它们抹成几块平涂色面。
- 网格与色数服务于造型。复杂珠宝、人像可用 32～40 格及足够的颜色；24～32 格和 6～8 色只是简单题材的参考，不要求减到 4 色或最低珠子数。
- 结构性明暗、高光和切面由图案数据表达，每颗珠子的表面光泽交给渲染。只合并无意义的噪点，不把材质层次、必要饰纹和有用背景框一起删掉。
- 人像特写、合理背景框或清楚短字等取舍按题材决定；用户指定已有优秀图案时，只读取该参考的相关结构。具体例子见设计规范。
- 大块搬运是次要优化方向。允许五官、切面边缘、镶爪等必要小色块，不为了连通、平均批量或步数把图案做粗糙。

## 制作与检查

按契约编辑 `template-core/colorever-new/src/patterns/<id>.json`。新增时同时补齐同目录的 `<id>.js`、`catalog.json` 与 `index.js` 注册；只有数据变化时沿用已有模块和注册。

运行本 skill 自带的只读校验器，用实际开局引擎检查选定图案，不需要阅读求解实现：

```sh
node .agents/skills/colorever-patterns/scripts/check-pattern.mjs <id>
```

校验器调用当前 `src/game-level.js`：`easy` 保留简易规则，`medium` 是编辑器的“适中 · 全局大块归位”。旧配置 `scattered` 在当前入口映射到全局模式，不另算一种玩法；旧 `src/level.js` 的 12～14 步适中测试不能代替此检查。

每张新增或修改的图案都检查全局模式，即使演示选择 easy。校验器先用 `coverage=95`；若无法求解或超过 80 次，自动保留同一完成图改用 `coverage=80` 复验。单批上限保持 30，使用图案演示 seed 和自身缓存参数。**选定错位比例下的完整解法不得超过 80 次成功搬运**；80% 通过即符合要求，无需强求 95%。一次入篮或归位算一次搬运，拾取点击不计步。80 次是搬运上限，80% 是必要时可选的错位比例，两者独立。

查看 JSON 的 `openingTrials`（95% 与必要时的 80% 结果）、`recommendedOpening` 和 `modes.medium`：步数、平均搬运数、大小批占比、缓存峰值和实际错位比例。平均搬运数只用于诊断，不设“至少 12 颗”等统一门槛，也不因均值偏低就强制减色或删细节。均值不包含缓存自动整理位移。

95% 操作量过大时，**先把错位目标改为 80%，而不是破坏已成立的造型、配色和材质层次**。80% 仍超标时，只优化不影响美感的碎色与冗余，并复验；仍有冲突则保留美观版本、如实报告未满足的开局预算，不宣称通过。不要靠挑选有利种子、增大单批/缓存或修改引擎掩盖问题。

交付必须明确选用的 coverage，并让实际预览、广告任务与校验一致；不能在 80% 下验证、却让用户仍从 95% 开局。源图案不保存广告开局参数。可显式检查选定参数，此时不自动回退：

```sh
node .agents/skills/colorever-patterns/scripts/check-pattern.mjs <id> --seed 123 --coverage 80 --batch-size 30
```

默认检查仅覆盖演示种子；随机种子交付再抽查 `1、7、31`。若某种子需要 80%，用统一的 80% 配置复验交付种子，每次都满足 80 次上限并记录结果。抽查不代表所有种子保证；用户明确指定的参数优先，实际缓存不同也应按任务配置复验。

需要让广告编辑器使用新数据时，使用现有定向构建，再比对该图案的产物、清单和哈希：

```sh
npm run build -w template-core/colorever-new
node .agents/skills/colorever-patterns/scripts/check-pattern.mjs <id> --built
```

只修改图案时不应改变 `game/game.js`、`game/level-engine.mjs`。检查这些文件的 Git diff；如果发生变化，先查清原因。构建产物通过构建更新，不手写生成区。

## 实际预览

复用正在运行的 Colorever New 开发服务；先确认地址对应本项目。没有可用服务时，从根目录启动：

```sh
npm run dev -w template-core/colorever-new -- --host 127.0.0.1 --port 5175 --strictPort
```

新服务的完成图地址为 `http://127.0.0.1:5175/api/patterns/<id>/preview?completed=1&renderer=new`；全局开局使用 `?completed=0&renderer=new&mode=medium&coverage=<选定的80或95>&batch=30&seed=<已校验种子>`，与报告一致。编辑器本身的默认值可能仍为 95，交付 80% 图案时应打开明确带 `coverage=80` 的测试链接。使用本次实际服务端口，不关闭或覆盖占用端口的服务。

在实际浏览器中按 320px、390px 宽检查完成图、开局和空槽，并试玩至完成；按设计规范判断效果。优先复用这些通用预览入口，不为每张图案复制一份专用打包或截图脚本。浏览器工具不可用时，保留已验证的数据结果，明确尚未完成视觉或触摸验收。

离线 HTML、ZIP、广告覆盖层和第二关接入仅在本次交付需要时处理；此时再读 [导出与集成](references/export-and-integration.md)。

## 何时展开读取

- 字段校验失败：先按错误和数据契约修正；契约与实现不一致时只读 `src/level.js` 的相关校验。
- 求解失败或全局超过 80 次：先确认已用 80% 错位复验且与任务参数一致；保留完成图美感。怀疑引擎问题时再读 `src/game-level.js`、`src/global-opening.js` 和必要的模型片段。
- 开发预览失败：先看浏览器错误、当前注册和服务地址，再查 `scripts/authoring.mjs` 或报错文件。
- 构建或哈希失败：先看命令输出，再查具体构建脚本；不回退到手改清单或绕过校验。

涉及玩法、渲染或公共流程改造时重新确定任务范围，不把它们混入普通图案制作。只需为真实的新逻辑或图案专有约束补充测试，通用格式和求解由现有工具验证。

交付图案 ID、尺寸、珠子数、用色、实际预览或截图，以及全局检查的参数、步数、平均搬运数和小批占比。区分自动检查与实际视觉验收；超过 80 次的图案继续调整，不标记为通过。是否提交遵循本次用户指令，不因使用 skill 自动提交。
