# 获取与载荷分析

## 从商店应用到素材

1. 从用户链接确定平台、商店 app ID、应用名与发行方；不依赖名称相同来认定同一产品。
2. 在 `data.insightrackr.com` 复用可用登录会话。登录、验证码或站点要求的额外访问权限按当前工具规则处理；不提取浏览器 cookies 或复制会话令牌到 shell。
3. 找目标应用的 playable 列表，读取当前 UI 支持的渠道、平台、时间、国家和排序条件。路线随网站变化；历史 `/app/detail/<id>/creative/preplay` 只作定位线索，不能假定参数含义不变。
4. 从筛选结果挑有代表性的候选，尽快亲自试玩。考虑教程是否清晰、交互是否真实、玩法深度、画面质量、移动端布局、下载载荷是否完整，以及改造成短视频接试玩的工作量。已有足够依据即可推荐，不为了凑候选数不断翻页。
5. 详情页/聚合页与下载载荷交叉核对 app ID 和发行方。落地 ID 一致支持“关联该应用”，不能单凭列表位置或相似画面证明版权归属或发行方自制。

记录候选指纹、稳定详情 URL、观察日期、筛选条件、展示的投放周期/量级、实测玩法和局限。对“效果好”区分估算投放信号与真实 CTR/CVR 数据；没有后者就不要推断转化率。

## 下载与证据保存

- 使用当前卡片/详情上的下载入口；先等待下载事件，再点击并核对实际保存路径、文件大小和内容。
- HTML 素材链接可能直接在当前页打开而没有产生下载。遇到这种情况回到可见的下载按钮；不要连续猜 URL 或把详情页 HTML 当 playable。
- 下载物可能只是很小的 loader。检查其中明确引用的脚本，获取真实载荷，直到能列清入口、核心和资源。公开资源可通过合适的下载工具读取；依赖登录的资源通过授权会话和站点下载路径获取，不搬运认证信息绕过访问控制。
- 先保存在研究目录。保留原始字节及 SHA-256，抽取/解码结果另存。下载链接带签名、token 或会话参数时不把完整地址写进报告或提交；稳定详情链接和指纹用于追溯。原始文件本身也需检查，不能因为是下载件就自动纳入仓库。
- 截图保存为实际可访问的文件。使用浏览器/截图工具展示，不为展示远程媒体另行规避平台的媒体访问限制。

## 离线辅助脚本

`scripts/inspect-playable.mjs` 支持本地 HTML 或 JavaScript，适用于识别结构，不负责自动移植：

- 原始输入逐字节保存，记录 SHA-256；输出目录存在时拒绝覆盖。
- 对精确的 `al_renderHtml({"html":"..."});` 形式用 `JSON.parse` 解包，不用 `eval` 或运行下载脚本。
- 抽出内联 script；在 JS 或内联脚本中尝试长 base64 字符串的 Brotli 解码，设置输入、输出和候选数量上限。
- 解码成功的 UTF-8 文本保存为 `decoded-*.txt`；可能是核心、数据或别的文本，需阅读后判断。未解码不代表文件损坏，候选也可能是图片/其他格式。
- 汇总外部 script/iframe/link 引用、可识别的 `editorParameters` 结构、资源集合数量和原版商店触发参数。报告中的 URL 去掉用户名、密码、查询和片段；该处理不改原始文件。
- 不解析任意 JS 表达式，不自动执行未知 wrapper，不连接 Insightrackr，不提供解压 ZIP 或通用反混淆能力。ZIP 先检查条目和根入口，再按可用工具安全解压；不是这个脚本的输入。

产物 `inspection.json` 中的 engine hints、脚本特征与链接只用于定位，不能替代人工核查和实际运行。未识别、候选截断、解码失败的数量会留在报告中。

## 找到能移植的边界

阅读可识别的配置和业务函数，避免把整个压缩引擎打印进上下文。优先小范围提取包含目标锚点的片段。

需要搞清：

- 资源载入与启动顺序、是否依赖 `mraid.js`/广告网络宿主、远程字体、纹理、WASM、音频或视频。
- 真正的选中、提交移动、消除/出门、关卡切换和最终成功/失败入口；异步动画和多个回调是否指向同一次操作。
- 原版何时打开商店：次数、时间、进度、消除数、结算定时器、logo、CTA、全屏点击及重玩等。
- 打开商店是否设置不可继续玩的状态、停止输入或提前发 `ad_end`。`ad_end` 名称本身不能证明获胜。
- 有无资源签名和配置冻结；保留合法原始资源/链接，通过适配入口治理行为，不靠删除校验来掩盖载荷不完整。无法满足的依赖明确报告。

## Block Out 案例：仅作阅读路线

若当前仓库包含以下文件，可以了解本次已落地的方法：

- `template-core/block-out-origin/source/provenance.json`：来源、原生跳转参数、冻结文件哈希。
- `template-core/block-out-origin/scripts/build.mjs`：HTML/Brotli 解包、唯一锚点、原始载荷与生成物的边界。
- `editor/plugins/block-out-origin/overlays/engine/engine.js`：移动和出门去重、原生商店入口治理。

这个案例是 PixiJS、2 + 37 块、两个原生关卡共一段试玩。混淆变量、`BMS` 数据结构、指纹、有效操作定义和 CTA 数值都不能复制给其他游戏。Cocos 可参考当前 `colorever-origin` 的冻结资源组织，但也要按目标素材重新定位。
