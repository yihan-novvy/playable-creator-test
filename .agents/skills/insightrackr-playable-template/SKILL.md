# Insightrackr playable → 项目模板

将指定游戏的真实 playable 变成当前 `playable-creator` 仓库可配置、可预览、可导出并接入事件的模板。优先保留原玩法核心，以确定性构建和独立适配层完成集成。

## 范围与项目定位

- 从本次对话确定游戏商店链接/ID、来源或候选、目标项目和授权阶段。用户已说“开发吧”或要求直接制作模板时继续开发；用户明确要求先分析、同意后开发时，只获取和分析，交付具体方案后等待该同意。不要把一次历史审批流程变成所有任务的额外审批。
- 以当前工作目录或用户指定仓库为根，确认 `template-core/`、`editor/plugins/`、`editor/templates/` 和根 `package.json`。个人安装的 skill 不代表所有仓库都适用；找不到目标项目时先定位，不能在其他项目套目录。
- 读取仓库适用的 `AGENTS.md`、`docs/template-plugin-spec.md`、`docs/original-zip-required-event-integration.md`。参考实现帮助理解代码，当前规范和任务要求决定行为。
- 不固定本次历史中的 app ID、素材指纹、下载地址、端口、混淆符号、关卡数量或 CTA 节奏。读取当前仓库/服务的真实配置。

## 获取与推荐

按 [获取与载荷分析](references/acquisition.md) 操作。优先使用足够完成任务的已连接工具；网站需浏览器时，复用已授权登录会话并按当前页面定位。需用户完成登录时清楚说明，继续不依赖登录的仓库分析。

确认目标应用与发行方，筛选实际可玩的候选，记录平台筛选范围、素材指纹、稳定详情页和观察日期。产品聚合页可能混入关联应用，必须核对候选落地商店 ID；“官方”身份不确定时明确保留不确定性。投放天数、展示量估算只作筛选信号，不等同于转化效果。

使用站内下载入口获得真实文件，再识别入口 HTML、loader、核心脚本与资源。离线辅助脚本：

```sh
node "$SKILL_DIR/scripts/inspect-playable.mjs" \
  --input "$DOWNLOADED_FILE" --out "$RESEARCH_DIR" \
  --source-url "$OBSERVED_DETAIL_URL"
```

`SKILL_DIR` 为本 skill 路径；`RESEARCH_DIR` 必须是不存在的新目录。脚本只读本地输入，保存原始字节、解析明确的 AppLovin JSON 包装及可识别的 Brotli 文本，不执行脚本、不请求网络。未知格式不会凭空“解出引擎”。详见参考中的能力边界。

分析阶段产出：推荐候选及依据、来源确认程度、可玩截图、原始文件与 SHA-256、引擎/资源/关卡/跳转依赖、可复用核心、事件接入点和拟开发范围。若开发授权已具备，这些材料形成实现依据，不再次停下来索要同意。

## 模板实现

开发前读 [项目适配与事件](references/integration.md)。

- 冻结获取的原始载荷并记录来源；在源项目构建中抽取、复制或补丁，校验源哈希和唯一结构锚点。不得手改 `editor/templates/` 的生成文件。
- 建立 `template-core/<id>/` → `editor/templates/<id>/`，以及 `editor/plugins/<id>/`。manifest 声明插件使用的资源路径；预览与 pack 共用组装逻辑。
- 简单“视频 + playable”优先复用 `core:intro`；pack 使用转码后视频与海报。只暴露本次有用的标题、视频、CTA 或关卡设置。
- 先界定本段有效操作、真实进度和最终结果，再选择事件桥。有效移动不一定提高完成度，不能无条件复用“进度上涨才记步”的桥。
- 将所有下载入口归一到项目 click API；停用原版自动跳转和回店后锁玩法的副作用。失败、胜利、离开与下载是独立语义。
- 尽量沿用插件扩展边界；当前实现若存在配置白名单等接入缺口，只作必要最小调整并注明原因，不顺带重构整个 editor。

## 验收与交付

按 [验收与交付](references/verification.md) 验证：构建/注册表、玩法与事件回归、纯试玩和视频两种链路、手机与横屏、打包后本地资源、工作台保存及 ZIP 导出。

报告“静态检查”“适配器模拟”“真实浏览器试玩”“生产 SDK / 真机广告 WebView”各自验证到的程度。完整过关没测就不能用第一关截图或 `onComplete` 字样宣称通关链路已经实测。

交付模板 ID、可试玩任务/产物、源码与插件位置、默认配置、验证结果及剩余限制。原始来源与必要生成文件进入模板交付；登录数据、带凭据的临时 URL、测试 SDK、测试任务和测试视频不得混入成品。Git 分支、提交、推送及发布按本次明确要求处理，不沿用历史任务已完成的 Git 操作。
