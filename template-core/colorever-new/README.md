# Colorever New · 立体宝石

从当前 colorever 完整复制的独立模板。升级珠子、光照及珠子表面的反馈，并加强空槽内壁的阴影；底部格子容器保持原有形状、尺寸、目标色和不透明度，图案、配色、专属装饰、开局生成、求解、缓存容量、移动与归位规则保持兼容。

## 视觉

- 珠子采用较浅的四切面和三段圆角倒边，沿用实例化渲染；主色与切面明暗使用保持色相的着色，避免整片亮面泛白。
- 珠子宽度约占格子宽度的 82%，尺寸适配原有槽位；周围露出固定目标颜色，错珠未拿走时也能辨认归位目标。
- 底部格子容器保持连续、不透明的目标色底板及原有槽位边沿；上侧和左侧内壁阴影更深、更宽，槽底带轻微明暗过渡。
- 每颗珠子上侧的完整切面以本色提亮；常驻反光只在圆角和上缘形成小亮点，少量珠子错开时机产生轻微的同色闪光。
- `/calibration.html` 同屏展示参考图的四种珠子、模板的实时珠子、移走珠子后的空槽和房子放大预览，共用游戏模型、色板、槽位及反光代码。
- 错珠边框贴近珠子，保留底色可见区域；点击范围仍按完整格子处理。
- 棋盘坐标、背景配置、HUD、缓存布局和容量沿用原版，兼容已有装饰。

## GPU 兼容

Playable 在所有设备上关闭实时阴影贴图，并移除地面投影接收层、棋盘珠子底部的接触阴影贴图，以及托盘内珠子的接触阴影层和对应状态维护。珠子材质、环境光、抗锯齿、槽位明暗及游戏规则保留。

Pixel 10 Pro XL 的无视频对照测试中，同一关在开启实时阴影时丢失上下文，关闭后可流畅交互。本模板统一使用无投影和无接触阴影的方式，不再按 GPU 型号分支。修改后需重新打包；完整 SDK 广告包仍需在实机验证。

## 开发与构建

在仓库根目录运行：

```bash
npm run dev -w template-core/colorever-new -- --host 127.0.0.1 --port 5175
npm run build -w template-core/colorever-new
npm test -w template-core/colorever-new
node editor/test/run-all.mjs colorever-new
```

图案画室使用本目录的 `npm run editor`，端口 5175。玩法源码和图案数据保存在本目录；构建只输出到 `editor/templates/colorever-new/`。不写入原版 colorever。

### 产物分层不变量

构建产物分三层，职责互不重叠：

- `game/game.js` 是纯引擎：不含任何图案关卡数据与装饰代码。新增图案不会改变 game.js 的字节与 `engineSha256`，只有引擎源码（src 下非 patterns 目录）变化才会触发重建差异。
- 图案关卡数据在 `game/patterns/<id>.json`（不含开局），广告任务在编辑器里按图案 + 开局配置经 `game/level-engine.mjs` 生成开局后，以 `window.__COLOREVER_LEVEL__`（第二关 `__COLOREVER_PHASE2__`）注入 index.html。
- 装饰代码在 `game/decorators/<id>.js`（构建期从 `src/patterns/<id>.js` 打出的注册片段，sha 锁定在 `game/patterns/catalog.json` 顶层 `decorators`）。导出与预览只把所选图案（主关 + 第二关，去重）的片段内联进 index.html 的 `data-colorever-decorators` 脚本。

在 editor 新建任务时选择 **Colorever New（立体宝石）**，ID 为 `colorever-new`。原版配置可以原样用于新任务，所有图案 ID 与数据字段保持不变。

七步流程与原版相同：片头 → 片尾 → HUD → 第一关背景 → 第二关背景 → 关卡 → 打包。支持任务音乐、开局模式与种子、第二 playable、CTA 时机和 ZIP 导出。

保留 `__COLOREVER_*` 运行时数据注入、`novvy:*` 事件和 SDK 接口。旧任务继续使用 `colorever`，不会自动迁移。图案编辑与构建仍然是单向流程；广告任务只选择已构建图案，不反写玩法源码。

回归检查将全部图案数据与开局引擎和原版逐字节比较，并比较每个图案在三种模式下的开局和求解结果。
